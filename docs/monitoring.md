# Prometheus and VictoriaMetrics monitoring

The monitoring stack is intentionally outside the measured inference path. The
benchmark writes one schema-v2 JSON snapshot, the update script atomically swaps
that file, and a separate C++ process exposes it in Prometheus text format.

```text
marketdata_ingress -> atomic metrics.json -> C++ exporter :9108
                                              |
                                              v
                                      Prometheus :9090
                                      rules + alerts
                                              |
                                         remote_write
                                              v
                                    VictoriaMetrics :8428
                                              |
                                              v
                                         Grafana :3000
```

No HTTP server, JSON parsing, mutex, counter update, allocation, or filesystem
operation is added to the timed inference loop.

## Build and test

```bash
cmake -S . -B build -DMD_REQUIRE_TENSORRT=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

The suite validates the C++ parser and exposition format, converts a real
schema-v2 document generated by `marketdata_ingress`, rejects malformed input,
and ensures mock output cannot expose a fabricated GPU timing distribution.

The dedicated `Monitoring Integration` GitHub workflow also starts all three
containers, validates Prometheus rules with `promtool`, proves exporter scraping,
queries remote-written data from VictoriaMetrics, verifies the provisioned
Grafana datasource and ten-panel dashboard, and uploads the resulting evidence.

## Start the local stack

Generate an initial snapshot:

```bash
mkdir -p runtime
build/bin/marketdata_ingress \
  --backend mock \
  --iterations 1000 \
  --warmup 100 \
  --target-us 10 \
  --json-out runtime/latest.json
```

Run the C++ exporter in a separate terminal:

```bash
build/bin/marketdata_metrics_exporter \
  --metrics-file runtime/latest.json \
  --listen-address 0.0.0.0 \
  --port 9108
```

Start Prometheus, VictoriaMetrics, and Grafana:

```bash
docker compose --env-file deploy/monitoring/.env.example \
  -f deploy/monitoring/compose.yaml up -d
```

Open Grafana at `http://localhost:3000`, Prometheus at
`http://localhost:9090`, and VictoriaMetrics vmui at
`http://localhost:8428/vmui`. The provisioned dashboard is named
`MarketData Edge Pulse`.

The example password is for loopback development only. Set
`GRAFANA_ADMIN_PASSWORD` to a secret and keep anonymous access disabled on any
shared machine.

## Continuous TensorRT evidence

Run repeated benchmarks with atomic publication:

```bash
MD_MONITOR_INTERVAL_SECONDS=10 \
./scripts/run_monitored_benchmark.sh \
  build-real/bin/marketdata_ingress \
  runtime/latest.json \
  -- \
  --backend tensorrt \
  --model runtime/identity.engine \
  --input-size 32 \
  --batch 1 \
  --warmup 5000 \
  --iterations 50000 \
  --verify-identity \
  --cuda-graph \
  --target-scope device \
  --target-us 1.0
```

Failed runs never replace the last valid snapshot. Prometheus freshness alerts
still detect that the retained evidence has stopped advancing.

## Exported metrics

- `marketdata_build_info`: version, revision, model, backend, runtime, and GPU.
- `marketdata_inference_latency_us`: p50, p90, p95, and p99 summaries by scope.
- `marketdata_inference_latency_mean_us`: mean by end-to-end or device scope.
- `marketdata_inference_latency_min_us`: minimum by scope.
- `marketdata_inference_latency_max_us`: maximum by scope.
- `marketdata_inference_latency_stddev_us`: standard deviation by scope.
- `marketdata_inference_host_overhead_p99_us`: full-path p99 minus device p99.
- `marketdata_inference_throughput_inferences_per_second`: call throughput.
- `marketdata_inference_throughput_samples_per_second`: sample throughput.
- `marketdata_inference_slo_*`: configured target, observed p99, and verdict.
- `marketdata_inference_validation_*`: correctness coverage and verdict.
- `marketdata_inference_fallback_used`: explicit mock-fallback indicator.
- `marketdata_inference_cuda_graph_enabled`: execution-mode indicator.
- `marketdata_metrics_file_timestamp_seconds`: freshness source timestamp.
- `marketdata_exporter_*`: scrape, parse failure, and readiness telemetry.

## Alerts

Prometheus evaluates alerts for exporter loss, snapshot parsing failure, stale
evidence, p99 SLO failure, mock fallback, failed output validation, and prolonged
non-CUDA-Graph TensorRT execution. Alert expressions and severity labels live in
`deploy/monitoring/prometheus/rules/marketdata.yml`.

An alert rule is not a notification route. Connect Alertmanager, PagerDuty, or
another receiver separately before calling notification delivery operational.

## VictoriaMetrics retention and queries

Prometheus remote-writes every scraped series to
`http://victoriametrics:8428/api/v1/write`. The default retention is 30 days and
can be changed with `VM_RETENTION`.

Useful PromQL queries:

```promql
marketdata:device_p99_us
marketdata:e2e_p99_us
marketdata:host_overhead_p99_us
marketdata:metrics_age_seconds
marketdata_inference_slo_pass
```

Grafana uses VictoriaMetrics as its default Prometheus-compatible datasource;
the second provisioned datasource points directly to live Prometheus for rule
debugging.

## Troubleshooting

### Prometheus target is down

Verify the exporter is bound to `0.0.0.0:9108`, then check
`http://localhost:9108/healthz`, `/readyz`, and `/metrics`. On Linux, ensure the
Docker engine supports the `host-gateway` mapping used by Compose.

### Exporter is alive but not ready

`/readyz` returns the schema or file error. Generate a new snapshot with
`--json-out` and publish it atomically. `/metrics` remains scrapeable and exports
`marketdata_exporter_last_load_success 0` when loading fails.

### VictoriaMetrics has no series

Check Prometheus status for the `victoriametrics` remote-write queue, then query
`vm_rows_inserted_total` from the VictoriaMetrics scrape target. Confirm that
`http://victoriametrics:8428/api/v1/write` resolves inside the Compose network.

### Grafana dashboard has no values

Check the `VictoriaMetrics` datasource, select `All` in the exporter-instance
variable, and widen the time range. The first samples appear only after the C++
exporter has loaded a valid benchmark snapshot and Prometheus has scraped it.

### Validate configuration without starting services

```bash
docker compose -f deploy/monitoring/compose.yaml config
docker run --rm \
  -v "$PWD/deploy/monitoring/prometheus:/etc/prometheus:ro" \
  prom/prometheus:v3.14.0 \
  promtool check config /etc/prometheus/prometheus.yml
```
